# `overgate` микросервис OverNode

`overgate` — HTTP forward proxy проекта. Реализован первый этап: конфигурация,
логирование и жизненный цикл слушателя в `internal/proxyf`, аналогичный `oversite`.
Маршрутизация пока не реализована: все запросы получают временный ответ
`501 Not Implemented`.

## Конфигурация

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `proxyf.listen_on` | `:2080` | IP и порт слушателя; пустой IP — все интерфейсы, порт 0 выбирает ОС. |
| `proxyf.http_proxy` | пусто | Будущий upstream: `http://host[:port]`. |
| `proxyf.yggstack_proxy` | пусто | Будущий Yggstack: `socks5://host:port`. |
| `proxyf.local_site` | пусто | Будущий локальный сайт: `http://host[:port]`. |

Адреса upstream проверяются при запуске, но пока не используются. Для HTTP
порт по умолчанию — 80. Credentials, путь, query и fragment в этих URL запрещены.
IPv6 в URL записывается в квадратных скобках. Слушатель принимает числовой IP
или пустой IP для прослушивания всех интерфейсов.

Конфигурация загружается общим пакетом: аргументы CLI выше переменных окружения,
затем файл и значения по умолчанию. Например, `PROXYF__LISTEN_ON=127.0.0.1:8081`.
Параметры `logging.*` соответствуют общему пакету логирования.
Используйте отдельный конфигурационный файл overgate: ключи `httpd.*` из файла
oversite строгий загрузчик не принимает.

## Локальный запуск

Из корня проекта:

```sh
go run ./overgate/cmd/overgate
```

Или после сборки:

```sh
make build
.local/bin/overgate
```

Проверка первого этапа:

```sh
curl --noproxy '' --proxy http://127.0.0.1:2080 http://example.com/
```

Ожидается `501` с текстом `proxy routing is not implemented`. `Ctrl+C` или
SIGTERM закрывает слушатель и завершает сервис с кодом 0. Ошибка конфигурации
или запуска приводит к коду 1; `--help` выводит справку с кодом 0.

## Контейнерный образ

Образ собирается из корня репозитория командой:

```sh
docker build -f overgate/Dockerfile .
```

Dockerfile использует `common` и `overgate`, создавая для них временный `go.work` непосредственно внутри build-stage. Исходники `oversite` в этот образ не попадают.

В итоговом образе используется непривилегированный пользователь `65532:65532`.
Процесс работает до сигнала остановки. По умолчанию слушатель открыт на всех
интерфейсах контейнера, порт 2080; публикация портов в основном Compose пока не настроена.
