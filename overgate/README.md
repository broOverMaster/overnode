# `overgate` микросервис OverNode

`overgate` — HTTP forward proxy проекта. Реализованы конфигурация, логирование,
жизненный цикл по образцу `oversite`, классификация запросов, пересылка HTTP
для `local` и `internet`, а также CONNECT и цепочка HTTP-прокси для `internet`.

## Разбор запросов и маршруты

Цель берётся из первой строки запроса, без подстановки из `Host`.
Для обычных методов требуется абсолютный URL `http://host[:port]/path`;
для CONNECT — `host:port` с обязательным портом. Обычный запрос `GET /path`
получает `400 Bad Request`. Неподдерживаемые схемы, credentials, fragment,
некорректные имена и порты также отклоняются с `400`.

| Имя назначения | Маршрут |
| --- | --- |
| `local.overspace` | `local` |
| Остальные имена с `.overspace` | `overspace` |
| Имена с `.ygg` | `ygg` |
| Остальные имена и IP-адреса | `internet` |

При сравнении имён игнорируются регистр и одна завершающая точка. Порт по
умолчанию для обычного HTTP — 80; исходные authority, path и query сохраняются.
CONNECT для `local`, `ygg` и `overspace` получает `405 Method Not Allowed`.
Для `ygg` и `overspace` проверяется hex-публичный ключ. Классификация
записывается в журнал при `logging.level=debug`.

## Конфигурация

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `proxyf.listen_on` | `:2080` | IP и порт слушателя; пустой IP — все интерфейсы, порт 0 выбирает ОС. |
| `proxyf.http_proxy` | пусто | Upstream HTTP-прокси: `host:port`, для HTTP и CONNECT. |
| `proxyf.yggstack` | пусто | Yggstack SOCKS5: `host:port`. |
| `proxyf.local_site` | пусто | Локальный HTTP-сайт: `host:port`. |

Адреса проверяются при запуске. Для `http_proxy` порт обязателен, схема
`http://` не указывается; IPv6 записывается как `[::1]:1080`.
Для `local_site` также требуется `host:port`, без схемы, с обязательным портом.
Credentials, путь, query и fragment запрещены.
Для `yggstack` действует тот же формат: например, `stack:1080` или `[::1]:1080`.
Переменная окружения — `PROXYF__YGGSTACK`; старое имя `yggstack_proxy` удалено.
IPv6 в URL записывается в квадратных скобках. Слушатель принимает числовой IP
или пустой IP для прослушивания всех интерфейсов.

Конфигурация загружается общим пакетом: аргументы CLI выше переменных окружения,
затем файл и значения по умолчанию. Например, `PROXYF__LISTEN_ON=127.0.0.1:8081`.
Параметры `logging.*` соответствуют общему пакету логирования.
Используйте отдельный конфигурационный файл overgate: ключи `httpd.*` из файла
oversite строгий загрузчик не принимает.

## Локальный запуск

Из корня проекта:

```sh
go run ./overgate/cmd/overgate
```

Или после сборки:

```sh
make build
.local/bin/overgate
```

Проверка текущего этапа:

```sh
curl --noproxy '' --proxy http://127.0.0.1:2080 http://example.com/
```

Ожидается ответ целевого сайта (при наличии сетевого доступа). Запрос
`curl --noproxy '*' http://127.0.0.1:2080/` без proxy-формы получает `400`. `Ctrl+C` или
SIGTERM закрывает слушатель и завершает сервис с кодом 0. Ошибка конфигурации
или запуска приводит к коду 1; `--help` выводит справку с кодом 0.

## Пересылка HTTP

`local.overspace` направляется на `proxyf.local_site` с `Host: local.overspace`.
Пример с локально запущенным oversite:

```sh
.local/bin/overgate --proxyf.local_site=127.0.0.1:8000
curl --noproxy '' --proxy http://127.0.0.1:2080 http://local.overspace/
```

Без `proxyf.http_proxy` маршрут `internet` соединяется с целью напрямую.
Переменные `HTTP_PROXY`/`HTTPS_PROXY` не влияют на исходящие соединения сервиса.
Метод, path/query, тело, статус, сквозные заголовки и трейлеры передаются;
редиректы возвращаются клиенту без автоматического перехода. Служебные заголовки
соединения и proxy credentials не передаются целевому сайту. Protocol Upgrade
пока не поддерживается.

Незаданный `local_site` приводит к `503`; ошибка соединения — к `502`, таймаут
установления соединения или ожидания заголовков — к `504`. Таймаут соединения —
10 секунд, заголовков ответа — 30 секунд. Потоковые тела передаются без общего
лимита времени; отмена запроса или остановка сервиса закрывает соединения.

Пересылка `local` и overlay-маршрутов от настройки HTTP upstream не зависит.

## Yggdrasil и overspace

Имена `<hex_public_key>.ygg` и `<hex_public_key>.overspace` принимают ровно
64 hex-символа (32-байтный публичный ключ Ed25519). IPv6 вычисляется официальным
пакетом адресации Yggdrasil v0.5.14. Это проверка формата ключа, не подтверждение
существования или доступности узла.

Соединение с вычисленным IPv6 идёт через SOCKS5 из `proxyf.yggstack`.
В SOCKS5 передаётся числовой IPv6, без DNS-разрешения имени. Исходный `Host`
сохраняется; порт назначения берётся из URL, по умолчанию 80. На TCP-соединение
и SOCKS5-handshake вместе отводится 10 секунд. HTTP-пересылка использует те же
правила передачи тела, заголовков и трейлеров, что и остальные маршруты.

```sh
.local/bin/overgate --proxyf.yggstack=127.0.0.1:1080
curl --noproxy '' -x http://127.0.0.1:2080 http://<hex_public_key>.ygg/
```

Неверный ключ возвращает `400`; незаданный `yggstack` — `503`; ошибка SOCKS5 —
`502`, таймаут — `504`. Прямого соединения или fallback в интернет нет.
CONNECT по-прежнему запрещён для обоих маршрутов (`405`). Резолвинг обычных
имён `.overspace` отложен в T-2. Для реальной проверки через два Yggstack-узла
из корня выполните `make -C tests/proxyf acceptance-up` и
`make -C tests/proxyf acceptance-check`.
Ручные команды и проверки отказов описаны в [документации стенда](../tests/proxyf/README.md).

## Приём HTTP из Yggdrasil

Входящий трафик обслуживает отдельный компонент `internal/httpin`. Его параметры:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `httpin.listen_on` | пусто | IP:port или :port; пустое значение отключает входящий слушатель. |
| `httpin.local_site` | пусто | Фиксированный backend `host:port`; обязателен при включённом слушателе. |

В основном Compose задано `HTTPIN__LISTEN_ON=:8080` и
`HTTPIN__LOCAL_SITE=oversite:8000`; порт 8080 не публикуется на хост.
Для приёма из overlay Yggstack должен направлять `-remote-tcp` на этот слушатель.
В приёмочном стенде используются второй overgate и второй oversite; входящий
слушатель там находится на loopback сетевого пространства второго Yggstack.

`httpin` принимает обычный `GET /path HTTP/1.1`, сохраняет логический `Host`,
метод, path/query, тело и сквозные заголовки/трейлеры. Все запросы направляются
только в `httpin.local_site`; ни Host, ни URL не выбирают маршрут. Absolute-form
proxy-запросы отклоняются с `400`, CONNECT — с `405`. Upgrade не поддерживается.
Ошибки backend возвращают `502`, таймаут соединения (10 секунд) или ожидания
заголовков (30 секунд) — `504`. Редиректы возвращаются без перехода.

`proxyf` и `httpin` запускаются с общим контекстом. Сигнал остановки или ошибка
одного компонента закрывает оба слушателя, активные запросы и CONNECT-туннели.
Аутентификация отправителя overlay не добавлена: httpin обслуживает запросы,
которые может доставить настроенный слушатель/Yggstack.

## HTTPS и цепочка прокси

CONNECT для `internet` создаёт TCP-туннель. Ответ `200 Connection Established`
отправляется только после соединения с целью или успешного CONNECT у upstream.
TLS остаётся между клиентом и целевым сервером, без перехвата сертификатов.
Туннели поддерживают half-close и закрываются при остановке сервиса.
На соединение и CONNECT-handshake отводится 10 секунд; установленный туннель
не ограничивается общим временем работы.

```sh
curl --noproxy '' -x http://127.0.0.1:2080 https://mail.ru/
```

Если задан `proxyf.http_proxy`, обычный HTTP и CONNECT идут через этот прокси.
При отказе upstream прямого fallback нет: ошибка CONNECT возвращает `502`,
таймаут — `504`. Аутентификация upstream пока не поддерживается.

```sh
.local/bin/overgate --proxyf.http_proxy=127.0.0.1:3128
```

## Контейнерный образ

Для приёмки используйте локальный `compose.override.yaml`, содержащий только
публикацию порта:

```yaml
services:
  overgate:
    ports:
      - "127.0.0.1:2080:2080"
```

Запустите `make up`. Основной `compose.yaml` задаёт связь сервисов:
оба сервиса подключены к сети `backend`, oversite слушает `:8000`,
а `proxyf.local_site` задаётся как `oversite:8000`.
Порт 8000 не публикуется на хост. Каталог сайта по умолчанию — `.local/var/www/html`.
Параметры задаются через Compose environment; локальные YAML-файлы конфигурации
в контейнеры не монтируются. Override игнорируется Git.

```sh
curl --noproxy '' -i -x http://127.0.0.1:2080 http://local.overspace/
curl --noproxy '' -i -x http://127.0.0.1:2080 http://oversite:8000/
curl --noproxy '' -i -x http://127.0.0.1:2080 http://example.com/
```

Первые два запроса возвращают сайт oversite через маршруты `local` и `internet`
соответственно. Имя `oversite` во втором запросе разрешается внутри Docker-сети.
Третий проверяет внешний HTTP-сайт и требует доступа в интернет.
Для HTTPS используйте `https://mail.ru/` через тот же прокси.
Остановка стенда — `make down`.

Образ собирается из корня репозитория командой:

```sh
docker build -f overgate/Dockerfile .
```

Dockerfile использует `common` и `overgate`, создавая для них временный `go.work` непосредственно внутри build-stage. Исходники `oversite` в этот образ не попадают.

В итоговом образе используется непривилегированный пользователь `65532:65532`.
Процесс работает до сигнала остановки. По умолчанию слушатель открыт на всех
интерфейсах контейнера, порт 2080; публикация портов в основном Compose пока не настроена.
