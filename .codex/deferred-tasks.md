# Отложенные задачи

Журнал открытых проблем и отложенных решений. Как только задача закрыта и исправление
попало в коммит, её описание удаляется из файла: здесь остаётся только то, что ещё
требует работы. Идентификаторы не переиспользуются, следующий свободный ID — `T-2`.

Закрытие подтверждается коммитом; в его сообщении указывайте ID задачи (например,
`T-1`), чтобы связь сохранялась в истории.

Формат записи:

- **ID** — сквозной номер вида `T-6`;
- **Дата** — когда зафиксировали;
- **Критичность** — `высокая`, `средняя`, `низкая`;
- **Статус** — `открыта` или `в работе`;
- **Где** — файлы и функции;
- **Решение** — что делаем, если уже понятно.

## T-1. Access logging для oversite

- **Дата:** 2026-09-12
- **Критичность:** низкая
- **Статус:** открыта
- **Где:** [`oversite/internal/httpd/httpd.go`](../../oversite/internal/httpd/httpd.go)

### Что происходит

`oversite` пишет в журнал запуск и остановку HTTP-сервера, но не записывает отдельные
HTTP-запросы. Стандартный `http.FileServer` не создаёт access log самостоятельно.

### Насколько критично

Статические файлы обслуживаются корректно, однако невозможно по журналу установить
метод, путь, статус ответа и длительность отдельного запроса.

### Варианты решения

1. Добавить middleware вокруг файлового обработчика, записывающий метод, путь, статус,
   размер ответа и длительность в переданный `slog.Logger`.
